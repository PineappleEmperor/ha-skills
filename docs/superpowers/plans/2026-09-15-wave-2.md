> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the two panel integrations from copied workflow bodies onto the
reusable-workflow stack, bring their code to 2026.9 practice, prove each with an rc
release, and feed what the skill got wrong back into it.

**Architecture:** One fresh clone per repository under `claude-skills/.tmp/work/`, one
subagent per repository following the skill literally and logging every gap. Both repos
serve a panel, so each carries the ha-panel-ci caller and the `frontend/` templates. Each
has copied scripts and extra workflows the stack has no equivalent for; the plan decides
each on evidence and the subagent records disagreement as friction. Runs after wave 1's
consolidation has merged.

**Tech Stack:** as wave 1, plus Node 22, esbuild, vitest, ha-panel-ci `v1.1.2`,
`home-assistant-frontend` pinned from core's manifest at the HA release the test harness
pins.

**Spec:** `docs/superpowers/specs/2026-09-15-five-repo-sweep-design.md`

**Prerequisites:** the skill-refresh plan and wave 1's Task 5 have merged.

## Global Constraints

- Nothing is committed or pushed until the maintainer says go for that repository.
- Every push touching `.github/workflows/` is the maintainer's, over SSH from the clone.
- The reviewer agent (`.claude/agents/reviewer.md`, brief `docs/review.md`) runs on every
  branch before a push is handed over.
- No AI-attribution trailer or line anywhere.
- Commit subjects: one imperative, Conventional Commit type, lowercase after the colon, no
  trailing period, no `and`.
- No version is ever hand-written; the release tag sets `manifest.json` at publish.
- Callers, not bodies; copies, not paraphrases; only the adaptations under *Sanctioned
  adaptations — the complete list* in `reference/github-actions.md`.
- Pins at the time of writing (re-resolve at execution; use the newer if moved):
  release-flow `aa2b6aaf8dadccd1f6ed5c65df774cf5f96091ae # v1.1.4`,
  ha-integration-ci `7aae20dcc8854e14197dd259d15f6368d1478eba # v1.0.4`,
  ha-panel-ci `cf32b7da07f7a31f68b6af1a3a80ef8b6f6ac3b7 # v1.1.2`.
- `panel / Panel type-check and tests` is never a required context (ha-panel-ci's README,
  *Calling the workflow*).
- Friction log: `claude-skills/.tmp/friction/<repo>.md`, one bullet per event:
  `- <reference file> · <heading> · said: … · true: … · did: …`
